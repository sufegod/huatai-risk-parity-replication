# 品种测试流程提示词

本文档用于把策略品种的新增、删除、替换测试固化为一套稳定流程。使用时，先填写“品种变更清单”，再把“提示词正文”完整复制给其他模型。

## 使用前填写

- 新增品种：填写品种名、资产类别、数据源信息、保证金比例、是否需要历史填充。
- 删除品种：填写需要从测试策略活跃资产池中剔除的品种名。
- 替换品种：填写 `旧品种 -> 新品种`。
- 测试名称：填写简短中文名称，例如 `TL删除测试`、`IC替换IM测试`、`XX新增测试`。

如果新增或替换进来的品种缺少数据源代码、保证金比例、资产类别、填充规则等关键信息，必须先补齐这些信息；不要让模型自行编造。

## 提示词正文

你现在位于“华泰风险平价策略复现”项目根目录。请始终用简体中文沟通，先读取项目现状，不要凭记忆假设最新版本。目标是在当前最新主策略基础上，对策略品种进行添加、删减或替换测试，生成完整测试结果，并在共同回测区间上与基准主策略对比。除非用户最后明确确认，否则不得把测试策略升级为主策略。

### 1. 先确认当前主策略与输入

1. 检查以下文件和目录，确认最新主策略版本、主策略脚本、每日更新入口和现有测试命名：
   - `策略复现与回测/每日更新策略/daily_update_strategy.py`
   - `策略复现与回测/每日更新策略/README.md`
   - `策略复现与回测/策略代码/`
   - `策略复现与回测/策略版本说明/`
   - `策略复现与回测/策略测试代码/`
   - `策略复现与回测/策略测试结果/`
2. 默认以每日更新入口 `STRATEGY_SCRIPT` 指向的正式策略为基准策略。当前若仍是本项目现状，应为 `v0.19`，但必须从文件中重新确认。
3. 读取或向用户确认品种变更清单：
   - 新增品种：`[填入品种名、资产类别、数据源信息、保证金比例、是否需要历史填充]`
   - 删除品种：`[填入品种名]`
   - 替换品种：`[旧品种 -> 新品种]`
   - 测试名称：`[例如 TL删除测试 / IC替换IM测试 / XX新增测试]`
4. 如果新增或替换进来的品种缺少数据源代码、保证金比例、资产类别、填充规则等关键信息，先询问用户，不要自行编造。

### 2. 日度收益数据检查与补充

1. 检查 `数据/日度收益数据更新/日度收益数据更新.py` 中的品种配置，重点看：
   - `FUTURES_ASSETS`
   - `OUTPUT_COLUMNS`
   - ETF、GC001、指数替代填充等特殊数据源配置
2. 检查以下数据文件是否已有测试策略所需的所有新增或替换进品种列：
   - `数据/日度收益数据更新/日涨跌幅_填充.csv`
   - `数据/日度收益数据更新/日涨跌幅_未填充.csv`
3. 数据处理规则：
   - 新增或替换进来的品种若不存在，必须补充数据更新逻辑和输出列。
   - 删除或替换出去的品种，不要从历史 CSV、缓存或输出列中删除；只从测试策略的活跃资产池中剔除。
   - `日涨跌幅_未填充.csv` 应代表真实可交易收益。
   - `日涨跌幅_填充.csv` 可用于权重估计所需的历史补齐。
   - 如需要用其他指数或旧数据补齐历史，必须在测试说明中写清楚。
4. 数据更新后至少执行必要校验：新增品种列存在、日期索引正常、填充版和未填充版口径符合说明。数据库不可用时，如果缺列无法补充，应停止并说明阻塞原因。

### 3. 生成品种测试策略代码与结果

1. 从最新正式主策略脚本复制生成测试脚本，不要从旧测试脚本继续派生，除非用户明确要求。
2. 测试脚本路径按现有规范：
   - `策略复现与回测/策略测试代码/资产风险平价策略{测试版本}（{测试名称}）.py`
3. 测试版本号按基准版本自动递增测试后缀：
   - 若基准为 `0.19`，且已有 `0.19_1`，则新测试默认用 `0.19_2`。
4. 测试输出目录按现有规范：
   - `策略复现与回测/策略测试结果/{测试名称}_v{测试版本}/`
   - 子目录包括：`净值/`、`指标/`、`仓位明细/`、`图表/`
5. 只修改与品种变更直接相关的配置和逻辑，包括但不限于：
   - `VERSION`
   - `INDEX_FUTURES`
   - `RISK_PARITY_ASSET_CLASSES`
   - `PLOT_ASSET_CLASSES`
   - `MARGIN_RATIOS_EXCHANGE_MIN`
   - `MARGIN_RATIOS_BROKER`
   - 输出路径和测试说明文件名
6. 不改变与本次品种测试无关的策略逻辑，例如调仓频率、交易成本、闲置资金收益、胜率口径、优化器参数，除非用户明确要求。
7. 运行测试脚本，生成：
   - 每日净值 CSV
   - 年度及全局指标 CSV
   - 日度仓位明细 CSV
   - 回测图表 PNG
   - 测试说明 Markdown
   - 核心指标对比 CSV

### 4. 与基准策略做共同回测区间对比

1. 不要只比较两个策略各自的 `全局 (Total)`，必须计算共同回测区间。
2. 共同区间定义：
   - `common_start = max(基准策略净值首个有效日期, 测试策略净值首个有效日期)`
   - `common_end = min(基准策略净值最后日期, 测试策略净值最后日期)`
3. 在共同区间内重新计算并输出对比指标：
   - 期末净值，区间内归一化为 1 起算
   - 年化收益
   - 年化波动
   - 夏普比率
   - 最大回撤
   - 日度胜率或当前基准策略实际使用的胜率口径
   - 平均资金占用，如两边都有可对齐的仓位明细
4. 生成共同区间对比文件和说明，建议命名：
   - `{测试名称}共同区间核心指标对比_v{测试版本}.csv`
   - `{测试名称}测试说明_v{测试版本}.md`
5. 测试说明必须写清楚：
   - 基准版本与测试版本
   - 品种添加、删除、替换明细
   - 数据是否新增、是否填充、数据源和限制
   - 共同回测区间
   - 指标差异表
   - 所有输出文件路径
   - 本测试未修改每日更新主策略入口

### 5. 验证要求

完成测试后运行至少以下检查：

```powershell
python -m py_compile 数据\日度收益数据更新\日度收益数据更新.py 策略复现与回测\策略测试代码\资产风险平价策略{测试版本}（{测试名称}）.py 策略复现与回测\每日更新策略\daily_update_strategy.py
python 策略复现与回测\策略测试代码\资产风险平价策略{测试版本}（{测试名称}）.py
python -m unittest discover -s tests
```

如果新增了测试脚本，应补充或更新单元测试，至少验证：

- 测试版本号正确
- 新资产池、删除资产、替换资产配置正确
- 保证金表与活跃资产一致
- 胜率口径未意外退回旧口径
- 输出目录位于 `策略复现与回测/策略测试结果/`

### 6. 最后询问是否升级为主策略

测试完成并展示共同区间结果后，必须暂停并询问用户：

“是否将该测试策略升级为新的主策略，并作为每日更新策略使用？”

用户未明确同意前，不得执行升级。

如果用户同意升级，再执行：

1. 生成新的正式版本号，例如基准 `0.19` 的下一正式版为 `0.20`。
2. 在 `策略复现与回测/策略代码/` 新建正式策略脚本：
   - `资产风险平价策略0.20（{简短说明}）.py`
3. 正式脚本输出目录改回标准目录：
   - `策略复现与回测/回测指标/净值/`
   - `策略复现与回测/回测指标/指标/`
   - `策略复现与回测/回测指标/仓位明细/`
   - `策略复现与回测/回测图表/`
4. 更新每日更新入口：
   - `策略复现与回测/每日更新策略/daily_update_strategy.py` 的 `STRATEGY_SCRIPT`
   - 相关描述中的版本号
5. 更新说明文档：
   - `策略复现与回测/每日更新策略/README.md`
   - 新增 `策略复现与回测/策略版本说明/v{新版本}策略版本说明.md`
6. 运行正式策略和每日更新跳过数据更新校验：
   - `python 策略复现与回测\策略代码\资产风险平价策略{新版本}（{简短说明}）.py`
   - `python 策略复现与回测\每日更新策略\daily_update_strategy.py --skip-data-update`
   - `python -m unittest discover -s tests`
7. 保留原主策略、测试脚本和测试结果，不删除历史数据列或历史输出。
